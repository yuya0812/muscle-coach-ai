# Spec: AI用途の再定義（記録パース + データ分析の言語化）

## Why（なぜ作るか）

現状のマッスルコーチAIは「LINEでAIにメニューを組んでもらい記録していく」流れだが、
中核機能である **メニュー生成・コーチング会話は「正解のない出力」** を生成している。

- 正解がないため品質を検証できず、ユーザーは良し悪しを判断できない → 信頼を損なう
- 非決定的なので「同じ依頼で違う答え」が出る（再現性の欠如）
  - 直前のセッションで「メニュー再現性ガード」を入れたが、これは症状への対処療法であり、
    根本原因（正解のない生成をしていること）は解決しない
- LLM の最も弱い使い方をしている

方針転換として、**AIの用途を「入出力が検証可能で再現性が高い」2つに絞る**：

1. **雑な入力 → 構造化記録**（入力と出力が1対1対応、正解が存在し検証可能）
2. **記録の集計・分析**（弱点・伸び悩みはデータから計算で出る。再現性が高い）

LLM の強みである「自然言語の入出力変換」だけを使い、
**判断・計算はコードが行い、AIは言語化のみ担う**。

## What（何を作るか）

### ユーザーストーリー

- トレーニーとして、LINEに「ベンチ60キロ10回3セット」のような雑なテキストを送るだけで、
  AIが正しく構造化してアプリ（Firestore）に記録してくれる。なぜなら、いちいち画面で
  項目を埋めるのが面倒だから。
- トレーニーとして、自分の記録をもとに「どの部位が弱いか」「どこで伸び悩んでいるか」を
  教えてほしい。なぜなら、自分ではデータを集計・解釈できないから。
  ただしその分析は**毎回同じデータからは同じ結論**であってほしい（再現性）。

### 受け入れ条件

#### 記録パース（既存の強みを維持・前面化）
- [x] LINEに自然文の記録（例「ベンチ60キロ10回3セット 今日は調子よかった」）を送ると、
      AIがパースして Firestore の `users/{userId}/workouts` に保存する
- [x] パース結果のサマリーをユーザーに返す（既存 `parseAndSaveWorkout` の挙動）
- [x] パースできない入力には、記録できなかった旨と入力例を返す
- [x] 記録保存経路は LINE（`parseAndSaveWorkout`）と LIFF（`saveWorkoutDirectly`）の2系統を維持

#### データ分析（計算はコード、言語化のみAI）
- [x] 「分析して」等のリクエストで、記録を集計した分析を返す
- [x] 弱点部位・伸び悩み等の**判定はコード**（`history.ts` の集計 + 追加の判定ロジック）で行う
- [x] AIは集計済みの数値・判定結果を「人間が読みやすい言葉」に変換するだけ
      （数値そのものを推測・捏造させない）
- [x] 同じ記録データからは実質同じ分析が返る（再現性）

#### マイルストーン（削除ではなく「作り替えて残す」）
- [x] 5/15/30回到達の**節目トリガー**（`checkAndPushMilestone`）は残す（モチベ維持の価値・回数は計算で出る）
- [x] 節目の**中身を「AI自由生成」→「コード集計 + AI言語化」に作り替える**
      - 5回: 弱点部位（`history.ts` の `underworkedMuscles` / `muscleTouchCounts` を流用）
      - 15回: 成長トレンド（初期5回 vs 最近5回の重量・回数差をコードで集計）
      - 30回: これまでのパターン集計（頻度・部位・強度の偏りをコードで算出）
      - いずれも AI は集計済み数値・判定を言語化するだけ。数値の捏造をさせない
- [x] マイルストーン分析は普段の「分析機能」と**集計ロジック・言語化プロンプトを共通化**する

#### 削除
- [x] メニュー生成機能（`generateWeeklyMenu` / `getTodayMenu` / `menuGenerator.ts`）を削除
- [x] コーチング会話（フォーム指導・栄養相談・一般会話・進捗会話の各ハンドラ）を削除
- [x] トレーナー3キャラの人格（コウ/ドクターK/アキラ先輩、`trainerCharacter.ts` の口調・thinkingMessage 等）を削除し、
      記録・分析に徹したシンプルな応答にする。`trainerType`/`trainerName` の扱いは Plan で精査
      （プロフィールやオンボーディングのキャラ選択も連動して整理）
- [x] 上記に紐づくプロンプトを削除（MENU/FORM/PROGRESS/NUTRITION/一般会話用 TRAINER_SYSTEM_PROMPT /
      TRAINER_PERSONA）。**ただしマイルストーン作り替えで使う言語化プロンプトは新設**（弱点/成長/パターンの
      言語化用に、旧 WEAK_POINT/GROWTH_TREND/PROGRAM_OPTIMIZATION を「集計値を渡して言語化させる」形に作り替え）
- [x] WORKOUT_PARSE_PROMPT は記録パースの中核なので**残す**
- [x] 上記に紐づく LINE コマンド（「メニュー作成」「メニュー作り直し」「今日のメニュー」の
      メニュー経路、フォーム/栄養/一般会話の意図分類経路）を整理。「分析」は新分析機能へ接続
- [x] 直前コミット(8d4ef91)で入れたメニュー再現性ガード等は、メニュー機能ごと消えるため不要になる

### スコープ外（今回含まない）

- LIFF アプリ側（React）の大幅な UI 改修。記録・分析の表示は既存 LIFF を活かす前提
  （ただしメニュー表示画面があれば導線の見直しは将来課題）
- 週次レポートの自動 push（`sendWeeklyReports`）を分析機能として作り直すか否かは別途判断
- X 自動投稿（集客）は今回の対象外、現状維持
- Stripe・プレミアムプラン仕様の変更（「AI相談 月5回」等の課金軸は分析機能に合わせて
  将来見直す可能性があるが今回は触らない）
- オンボーディングの初回メニュー生成削除に伴う「初回体験の代替」設計（別タスク）

## 確定した方針判断（ユーザー承認済み）

- **マイルストーンは「作り替えて残す」**（削除しない）。トリガー維持、中身をコード集計+AI言語化に。
- **トレーナー3キャラの人格は削除**。記録・分析に徹したシンプルな応答にする。

## 未確定事項（最大3点）

     結果を LINE に返す。LIFF の `/dashboard`（既存の数値・グラフ）はそのまま維持し、
     LINE 分析は「数値の言語化サマリー」を担う。

2. **キャラ削除に伴う `trainerType`/`trainerName` の後始末**
   → 仮決定: データモデル上のフィールドは即削除せず残置（既存ユーザーデータ保護）。
     新規の参照（口調分岐・sender.name へのキャラ名注入）をやめる。オンボーディング/プロフィールの
     キャラ選択 UI を外すかは Plan で精査（LIFF 改修はスコープ外寄り）。

3. **オンボーディング完了後の初回メニュー生成削除の扱い**
   → 仮決定: 初回メニュー生成（`onboardingFlow.ts`）は削除し、完了メッセージを
     「記録の使い方案内（雑に送れば記録できる）」に差し替える。

## 設計原則の変更（CLAUDE.md）

- 現行原則「**LIFF=記録 / LINE=コーチング**」を見直す。
- 新原則案: 「**LIFF=閲覧・ダッシュボード / LINE=記録の入口＋分析の言語化**」。
  - LINE は「コーチが語る」場所ではなく「雑に記録を投げ込み、集計結果を言葉で受け取る」場所へ。
  - トレーナーキャラ（コウ/ドクターK/アキラ先輩）の人格は**削除**（確定）。
    記録応答・分析言語化は人格を持たない簡潔な口調にする。
- この変更は CLAUDE.md / AGENT_HANDOFF.md / NEXT_TASKS.md に反映する。
