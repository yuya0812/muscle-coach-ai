# Spec: LIFF UI を AI記録アプリの新設計に合わせて改修

## Why（なぜ作るか）

方針転換（[ai-scope-pivot.md](ai-scope-pivot.md)）でバックエンドは「記録パース + 分析の言語化」に
絞ったが、LIFF フロントには旧設計（メニュー生成・コーチング会話・トレーナー3キャラ）の
UI と文言が残っている。ユーザーが触る画面が「廃止した機能」を案内している状態で、
新設計の体験（雑にLINEへ送れば記録される / コード集計+AI分析）と矛盾している。

加えて、機能的には「AIを使った記録アプリ」なので、その性格に合った高級感のある
UIに引き上げたい。デザインの軸（Design DNA）はユーザー承認済み:

- 支配色: ダークネイビー基調。LINE green は「今アクションできる/達成した」意味に限定。
  gold は「まだ届かない価値（プレミアム・次のマイルストーン）」の一点豪華
- 数値を主役にした「計器盤」トーン（大きい数字 + 小さい大文字風ラベル）
- 静かな動き（fadeUp のみ）、カードは大角丸 + 極薄ボーダー

## What（何を作るか）

### ユーザーストーリー

- ユーザーとして、アプリを開いたときに「LINEに雑に送れば記録できる」とすぐ分かりたい。
  なぜなら、それがこのアプリの一番の価値だから。
- ユーザーとして、設定画面に「もう機能しないトレーナーキャラ選択」が出ていて混乱したくない。
- ユーザーとして、自分のトレーニングデータが「ちゃんとしたアプリ」として綺麗に見えてほしい。

### 受け入れ条件

#### 旧設計UIの除去（方針転換との整合）

- [ ] 設定（Profile）から「トレーナー名」「トレーナーキャラクター」の入力・表示UIを削除する。
      `trainerType`/`trainerName` フィールド自体は Firestore に残置（既存ユーザー保護、
      バックエンド方針と同じ）。updateProfile から該当フィールドの送信をやめる
- [ ] ダッシュボードの「AIコーチに相談する/LINEで何でも聞ける専属トレーナー」カードと、
      その例文（メニュー提案・フォーム相談・停滞打開）を撤去する
- [ ] オンボーディングの「今日のメニューを提案」「フォームのアドバイス」「停滞期の打開策を相談」を
      新設計の文言（記録・分析）に差し替える
- [ ] セットアップ（Setup）の「メニューや強度を判断」「メニューを提案」の文言を差し替える
- [ ] プラン（Subscribe）の特典リストから「AIパーソナルトレーナー無制限」「目標別パーソナル
      プログラム作成」を、新設計の特典（AI分析・週次レポート等）に差し替える
- [ ] プロダクトツアー（tour/steps.ts）の旧説明（メニュー提案・フォーム相談）を差し替える

#### 記録導線 + 分析要約（新設計の主役）

- [ ] ダッシュボードに「LINEでサッと記録」導線カードを置く。実際の入力例
      （「ベンチプレス 60kg 10回 3セット」）をチャットバブル風に見せ、
      「LINEで記録する」「分析してもらう」の2アクションを持つ（既存 closeLiff /
      sendMessageAndCloseLiff を利用）
- [ ] ダッシュボードに「分析サマリー」カードを置く。弱点/伸びているところ/伸び悩み/
      次のステップの4セクションを計器盤的に表示する（色分け: 弱点=muted、伸び=green、
      伸び悩み=gold寄り、次の一歩=primary枠）
- [ ] 分析サマリーは記録がないユーザーには「記録がたまると分析が見られる」案内を出す

#### 高級感（現テーマの洗練）

- [ ] theme.ts は土台として維持。必要なら計器盤強化のためのトークン（微光ハイライト等）を追加
- [ ] 数値表示の対比を強化（大数値のトラッキング、単位・ラベルの縮小）
- [ ] 分析サマリー・記録導線カードに上面ハイライト等の微細な質感を加える
- [ ] Design DNA の Don't（green ばらまき / フォント追加 / 濃い影・グラデ）を犯さない

### スコープ外

- バックエンドAIの挙動変更（分析ロジック自体は前回実装したものを使う）
- LINE側（リッチメニュー・トーク）の変更
- 新しいページの追加（既存5タブ構成は維持）
- Chart.js のグラフ種類の刷新（既存のレーダー/ライン/履歴は維持。見た目の微調整は可）
- Stripe・課金フローのロジック変更（文言のみ）

## 未確定事項（最大3点）

1. **分析サマリーカードのデータ源（コスト設計）** → 仮決定: ダッシュボード表示用は
   `buildAnalysis`（Claude API・課金あり）を毎回呼ばず、**コード集計だけの軽量サマリー**
   （弱点/伸び/伸び悩み/次の一歩を history.ts の集計から組み立て、AI言語化なし）を返す
   新APIを `/api/analysis-summary` として追加する。AIによる文章化は従来どおり LINE 側の
   「分析して」に任せ、ダッシュボードは「事実の要点」を無料・低レイテンシで見せる役割にする。
   （buildAnalysis を毎回叩くとダッシュボードを開くだけで課金・数秒待ちが発生するため）
2. **記録導線の「分析してもらう」ボタンの挙動** → 仮決定: 既存 WorkoutInput と同じく
   `sendMessageAndCloseLiff("分析して")` で LINE に送って閉じる。設定の autoSendAnalysis
   とは独立（ダッシュボードからは固定文言「分析して」を送る）。
3. **オンボーディングのフロー文言の粒度** → 仮決定: 「01 LINEで記録（雑に送るだけ）/
   02 このアプリでデータを見る・分析を受け取る」の2カード構成に作り替え。トレーナー要素は出さない。
