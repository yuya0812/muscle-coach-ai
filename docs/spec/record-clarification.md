# Spec: 記録パースの聞き返し（不足情報の補完フロー）

## Why（なぜ作るか）

自然文の記録パースは「雑に投げれば記録される」のが価値だが、現状は重量・回数・セット数が
読み取れない場合も null のまま保存している。記録アプリとして不完全な記録が積み重なると、
集計・分析の土台（部位バランス・成長トレンド）が崩れる。

パース後に不足情報を検出し、**最小限の聞き返し**で補完してから保存することで、
「雑に入力できる」体験と「記録の完全性」を両立する。

聞き返しは「検証可能な構造化記録」を強める方向であり、AI用途の方針
（[ai-scope-pivot.md](ai-scope-pivot.md)）と整合する。何が欠けているかの判定はコードが行い、
質問文は定型文（AI不使用）で再現性を保つ。

## What（何を作るか）

### ユーザーストーリー

- トレーニーとして、「スクワット80キロやった」のような不完全な入力を送ったとき、
  「何回×何セットでしたか？」と聞き返してもらって完全な記録にしたい。
  なぜなら、後から見返したとき・分析したときに使えない記録になるのは嫌だから。

### 受け入れ条件

#### 欠損検出と聞き返し

- [x] LINE経由の自然文パース後、weight / reps / sets の欠損をコードで検出する
- [x] 欠損があれば保存せず保留し、Quick Reply ボタン付きの定型質問で聞き返す
      （例: セット数 → 1〜5 のボタン、重量 → 数値入力を促す定型文）
- [x] 聞き返しは**最大2問まで**（ユーザー決定 2026-06-11）
- [x] 回答を保留レコードにマージし、欠損が解消したら保存する
- [x] **自重種目は weight を聞かない**（プッシュアップ・チンニング・クランチ・プランク等の
      自重種目リストをコードで管理し、weight null を正常として扱う）

#### 離脱・保存の挙動（ユーザー決定 2026-06-11）

- [x] 聞き返し中に回答以外のメッセージ（別の記録・分析依頼・雑談等）が来たら、
      保留レコードを**破棄**する。中途半端な記録は保存しない
- [x] 破棄後は、新しく来たメッセージを通常通り処理する（破棄の警告等は出さない）
- [x] 「保存しました（記録しました）」メッセージは**実際に保存したときだけ**送る
- [x] 2問の聞き返しで埋められない欠損が残る入力（3項目以上の欠損）は、聞き返しを
      始めずに「情報が足りない」案内と入力例を返し、保存しない

#### 既存挙動との整合

- [x] 完全な入力（欠損なし）は従来通り即保存・サマリー返答（聞き返しを挟まない）
- [x] 既存のボタン記録フロー（recordingFlow のステートマシン）と状態が衝突しないこと
- [x] マイルストーン発火（checkAndPushMilestone）は保存成功時のみ行う（従来通り）

### スコープ外

- LIFF 経由の記録（saveWorkoutDirectly）— フォーム入力でありクライアント側で完結する
- パース結果自体の確認ダイアログ（低 confidence 時の「この内容で合ってますか？」）— 別タスク
- 保存済み記録の編集・補完機能
- 質問文のAI生成（定型文のみ使う）

## 未確定事項（最大3点）

1. **「回答」と「離脱」の判定方法** → 仮決定: 保留中は受信メッセージをまず回答として
   解釈（数値・Quick Reply の postback・「なし」等）。解釈できなければ離脱とみなし
   破棄して通常処理に流す。
2. **複数種目で欠損がある場合** → 仮決定: 質問上限2問は入力1メッセージ全体で共有。
   2問で全種目の欠損が埋まらない場合は聞き返し自体を行わず「情報が足りない」案内に倒す。
3. **保留レコードの保管場所と寿命** → 仮決定: 既存 recordingFlow のステート保管先
   （Firestore）に相乗りし、明示的な離脱でのみ破棄（時間によるタイムアウトは設けない。
   既存ボタンフローと同等の扱い）。
