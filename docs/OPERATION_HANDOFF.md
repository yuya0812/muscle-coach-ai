## このアプリの本質（絶対に揺らがせない核）

「**雑にLINEに送るだけでAIが構造化記録し、蓄積データから伸び・継続・伸び悩みを言語化して返す
筋トレ記録アプリ**」。

- AIの用途は2つだけ: ①雑な入力を構造化記録 ②記録を集計してデータ分析を言語化
  （判定はコード、AIは言語化のみ）
- **廃止済み機能（復活させない）**: AIメニュー生成・フォーム指導・コーチング会話・
  トレーナーキャラ人格。理由は「正解のない生成は再現性も検証性もなく信頼を損なう」から
- **分析は「伸び中心」**。部位の網羅性で責める「弱点」は廃止済み。「最近やっていない種目」は
  累計30回で解放・デフォルトOFF（責めない）。ターゲットは網羅志向のマッチョではなく、
  30代サラリーマンの初心者〜中級者
- 差別化の核: 「個人の全記録の蓄積 × 同じデータから同じ分析が返る再現性」
  （ChatGPTには真似できない）

運用でユーザーの声を反映する際、この核を崩す要望（「メニューも作って」等）が来たら、
安易に実装せず**核との整合を必ず確認**する。過去に苦労して捨てた路線なので。

## 運用フェーズのゴール（段階的・迷ったときの判断軸）

集客はXのプロフィール経由でユーザーを輸入する形が動き始めた段階。ゴールは2段階:

- **フェーズ1（今ここ）**: レビュー収集 → 改善 → 定着。まず使い続けてもらう。
  ユーザー数が少ないので転換を急がない
- **フェーズ2（定着が回り出したら）**: 無料→プレミアム転換（売上）をKPIに

迷ったら「今はフェーズ1か2か」で判断軸を切り替える。フェーズ1では「使い続けてもらえるか／
フィードバックが取れるか」、フェーズ2では「転換に効くか」を基準にする。

## 運用に使える実装済み資産（ここを起点に動く）

すべて本番稼働中:

- **レビュー収集**: `functions/src/line/reviewFlow.ts`。ユーザーが累計3通送ると1度だけ感想を
  促し、返信を Firestore の `reviews` コレクションに保存。**ここに溜まる生の声が改善の一次ソース**
- **X自動投稿**: `functions/src/x/autoPost.ts`。1日3回（朝昼夜）、Haikuで生成。CTAあり/なしを
  週替わりでA/Bテスト（`ctaVariant`）。投稿テーマは曜日別（`DAILY_THEMES`）。本文は記録×分析
  アプリの世界観に固定済み。**noon/eveningが間欠的に403で落ちることがある**
  （観察中、retryCount=2で拾い直す設計）
- **X投稿ログ**: Firestore `xPostLogs`（doc ID = `YYYY-MM-DD_<timing>`）。成功/失敗・
  ctaVariant・timing を記録
- **Xメトリクス回収**: `functions/src/x/metrics.ts`。毎日3:00 JSTに各投稿の
  impressions/likes/retweets を取得し xPostLogs に書き戻す。手動トリガ
  `POST /api/admin/collect-x-metrics`（ADMIN_API_KEY 必須）。
  **「どのツイートが伸びたか」の分析材料がここに溜まる**
- **分析ロジック**: `functions/src/ai/analysis.ts`（`selectHighlights` = コード判定、
  `ANALYSIS_VERBALIZE_PROMPT` = AI言語化）
- **課金**: Stripe（¥1,480/月、トライアル1週間）。フリーはAI分析 月5回

## 3つの運用ループ（あなたの主な仕事）

1. **レビューを反映する**: `reviews` コレクションの声を読み、改善点を見つけ、
   コード/プロンプトを直してデプロイ。「使いにくい」が出たら最優先
2. **アップデートしていく**: 定着・転換に効く機能改善。実装は spec→plan→実装の流れ
   （`docs/spec/` 参照）。核を崩す要望は要確認
3. **ツイート内容を伸ばす**: xPostLogs のメトリクスを集計し、伸びた投稿の共通項
   （ctaVariant・曜日テーマ・文体）を `DAILY_THEMES` / `buildSystemPrompt` に反映。
   **ただしまだメトリクスが十分溜まっていない可能性が高いので、まず数日分のデータがあるか
   確認してから分析する**

## 仕事の進め方（このプロジェクトの確立した型）

- **破壊的操作（デプロイ・コミット・push・削除）は実行コマンドを提示して明示承認を得てから**。
  ユーザー（guttiiさん）は設計議論を好むので、勝手に方針を決めず選択肢を出して判断を仰ぐ
- **コミット**: Conventional Commits。末尾に
  `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`
- **デプロイ後は検証**: 特にhostingは**単独で `firebase deploy --only hosting`**
  （一括だとliveが更新されない事故が2回発生、CLAUDE.md参照）。配信JS名がローカルビルドと
  一致するか確認
- **mainブランチ運用**: ブランチは切らずmain直運用してきたが、push は確認を取る。
  実験的UIは `proto/ux-maximal` ブランチに全部盛りプロトが残っている
  （証明カード・蓄積メーター・Wrapped等。本番化候補の叩き台）
- **絵文字禁止**: 生成物すべてに適用（コード・コミット・Slack草稿・ツイートプロンプト・
  ドキュメント）。`lucide-react`等のアイコンコンポーネントはOK
- **セカンドオピニオン**: 設計大変更時は Codex レビュー（`/codex-review`）を取る運用。
  ただしChatGPTアカウントの使用量上限で止まることがある

## 既知の罠（CLAUDE.md「既知の罠」節に詳細）

  `credit balance is too low` が出たら即課金

- Node.js 20ランタイムが2026-10-30廃止予定（別途対応要）
